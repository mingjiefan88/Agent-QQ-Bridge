# Agent QQ Bridge

把 QQ 群聊接到你使用的 Agent，让机器人能聊天，也能处理群里的日常事务。

**当前阶段：开发预览。此目录提供产品方案、配置流程和可运行的连接诊断模块，尚不能安装为完整聊天机器人。**

目标是让 Codex、DeepSeek Harness（DSH）及其他 Agent 共用一套 QQ 接入核心。人格、群聊上下文、主动接话、戳一戳、群管理、语音点歌和媒体能力由核心与各引擎共同提供；不能用的能力会显示具体原因。

## 运行连接诊断

需要 Node.js 22 或更新版本。本预览不安装依赖，不启动 QQ，不发送群消息，不执行管理操作。

```sh
npm test
npm run diagnose
```

默认检查本机 OneBot 的 3000 端口。若接口未就绪，可明确指定 NapCat WebUI 配置文件，让诊断进一步区分等待扫码、初始化和离线状态：

```sh
node bin/diagnose.mjs --webui-config "你的NapCat目录/config/webui.json"
```

也可使用 `--onebot http://127.0.0.1:3000 --webui http://127.0.0.1:6099`。诊断入口只接受本机 HTTP 地址。配置路径由你指定，管理密钥不会写入输出。成功退出码为 0，连接未就绪为 1，参数或配置错误为 2。

`/get_login_info` 返回了账号资料，不代表 QQ 仍在线。这里同时检查 `/get_status`，失败后才查询本机 WebUI 登录阶段。QQ 服务器撤销登录票据时仍需重新授权，诊断模块不会反复重启 QQ 或绕过验证。

## 计划中的安装体验

1. 检测运行环境及已安装组件，失败项可单独修复。
2. 选择 Agent，完成授权与真实连接测试。
3. 连接 NapCat，直接展示登录二维码和账号状态。
4. 绑定主人、选择允许的群，读取真实群角色。
5. 选择人格与功能，展示权限和能力缺项。
6. 检查配置并启动；发送测试单独确认目标和内容。

流程支持返回、保留输入、刷新二维码和继续上次配置。详细方案见 [配置引导](docs/onboarding.md)。

## 功能边界

主人和管理权限依赖真实 QQ ID、群 ID、群角色以及本地授权。人格中的“主人”称呼不能授予管理权限。群消息、模型回复不能修改白名单或配置。

低频接话基于后续群消息触发；不保证固定时间自动发言。语音点歌计划从公开 B 站来源提取音轨并转 QQ 语音，支持关键词或指定 BV，受源可用性、长度和访问限制影响。生图按引擎实际能力启用，不承诺所有平台具备 Codex 的相同工具。

监控展示任务阶段、公开摘要（若引擎提供）和投递结果，不展示内部推理原文。

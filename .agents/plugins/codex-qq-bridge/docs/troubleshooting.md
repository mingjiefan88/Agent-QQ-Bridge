# 故障排查

| 现象 | 处理 |
| --- | --- |
| 一键启动提示端口被占用 | 默认3790，启动器不会杀其他进程；先检查已有窗口或本地config.json中的port，选择未占用端口 |
| Codex路径无效 | 使用桌面版自带codex.exe，或npm安装中实际可执行文件；不要把工作目录当可执行文件 |
| Codex未登录 | 点登录并在官方页面完成授权，再检测。CLI与桌面会话可能有不同授权状态 |
| 二维码未显示 | 确认QQ.exe路径，NapCat启动后等待初始化，查看NapCat日志；原生界面可处理特殊验证 |
| QQ已登录但接口未就绪 | 登录页点完成连接配置。自动重载未生效时，只停止并重新启动本安装的NapCat |
| 显示账号但不在线 | 只有get_status明确online且登录信息成功才视为在线。旧账号信息不能证明在线，票据失效需手机重新授权 |
| 机器人不回复 | 检查顶部是否已启动、群绑定、屏蔽、是否@或在续聊窗口；语音输入未提供转文字 |
| 群管失败 | 主人和机器人都需该群真实管理身份；昵称相同不能授权。目标用QQ号或明确@，遇到同名不会猜 |
| 点歌失败 | 安装下载组件、确认NapCat原生转码模块存在。部分音源不可访问或超时；不会自动重发不明结果 |
| 生图不可用 | 当前Codex账号/CLI可能没有原生生图工具。控制台显示真实失败，不会用伪造图片代替 |
| 监控没有内部思维 | 仅显示模型公开进度/摘要与工具状态，这是预期行为 |
| 插件MCP报node不存在 | 先双击启动器建立便携Node运行时；MCP包装脚本会复用它。也可安装Node22以上 |
| 数据损坏 | 停止实例，备份整个数据目录后检查具体报错文件，不自动覆盖损坏文件 |
| 发链接后 Agent 没自动填主人或群 | 私人身份不在仓库里；提供自己的真实 QQ 号与明确允许的群，或在控制台填写，不根据昵称推断 |
| bootstrap 提示有服务占用控制台端口 | 先检查本安装的已有控制台，正常暂停、等待任务结束并停止控制台后再改配置；若是其他服务，选择未占用端口，不杀进程 |
| bootstrap 提示安装目录已修改 | 不覆盖该目录；使用原安装，或指定新的空目录安装新版，保留私人数据目录 |
| 下载正式包提示无 Release 或找不到资产 | 确认 GitHub 最新正式 Release 是否已有 Windows 完整包和同名 `.zip.sha256`；未发布时不能当成已安装，不默默降级 beta |
| SHA256 不一致或包内文件未列出 | 停止安装并删除这份下载后重新获取；不要跳过校验或运行可疑文件 |
| 群里聊得快时没有逐条回答 | 普通群消息先合并；低频约2秒，高频等连续6秒安静，同群还有30秒/4次每5分钟限额。看监控“正在合并话题”和额度状态 |
| 主人静默后喊名字仍不答 | 属于预期：静默持久保存，只有已绑定主人通过QQ实际@机器人能解除；引用、唤醒词、@全体与其他人@均不行 |
| EigenFlux 显示待官网确认 | 本人在实际返回的官方页面完成邮箱、公开资料与边界/意图确认，再检查连接；安装CLI或生成链接不等于已连接 |
| EigenFlux 无动态或报错 | 查看独立页面与监控；未配置、授权不全、网络或服务限流都可能阻止读取，但不应阻断QQ基本聊天。不要上传群聊或反复调用模型补猜 |

“检查与调试”中的诊断没有真实QQ外发。先复制摘要帮助定位；不要把config.json、NapCat账号目录、二维码、授权代码或完整聊天日志上传到公开Issue。

首次安装完整流程见 [Agent 安装指南](agent-install.md)，人工配置步骤见 [使用说明](usage.md)。EigenFlux 属于可选接入，具体身份、授权和隐私边界见 [EigenFlux 指南](eigenflux.md)。
